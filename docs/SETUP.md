# Подключение EL_Store

1. Разверните этот репозиторий как отдельный Cloudflare Worker через `npm run deploy` или интеграцию Workers & Pages. Конфигурация `wrangler.jsonc` создаёт отдельное SQL Durable Object `NewsletterStore`; используйте отдельное имя `el-store` и не меняйте привязку CR_Reserve.
2. В настройках Worker задайте **Secrets** `BOT_TOKEN` от @EL_Store_Bot, `ADMIN_IDS` (числовой Telegram ID владельца; несколько ID через запятую) и `ORDER_CHAT_ID` (ID рабочего канала `-100…` либо `@username` публичного канала). Токен храните только в Cloudflare, не в GitHub и не в коде. `WEBHOOK_SECRET` необязателен: кнопка «Подключить бота» безопасно создаёт собственный секрет в хранилище.
3. Добавьте @EL_Store_Bot администратором канала с разрешением публикации. Для приватного канала после установки `BOT_TOKEN` и `ADMIN_IDS` откройте бота и перешлите ему сообщение из канала с сохранением источника. Он сообщит ID канала; внесите его в `ORDER_CHAT_ID` и повторно разверните Worker.
4. В @BotFather создайте Mini App для @EL_Store_Bot, укажите **фактический HTTPS-адрес** нового Worker. Если BotFather выдаст короткую ссылку вида `https://t.me/EL_Store_Bot/<app>`, используйте её для входа. Меню бота также настраивается внутри приложения.
5. Откройте Mini App своим Telegram-аккаунтом → **Управление → Подключить бота**. Это настроит webhook, команды и кнопку «Поступление». Если нужно, `npm run dev` предоставляет локальную проверку, но вход Telegram и доставка в канал требуют публичный HTTPS.
6. Добавьте менеджеров в «Управление → Менеджеры», затем «+ Поступление» → загрузите Excel → проверьте товары, цены и замечания → статус «В продаже» → сохраните. Поддерживается отчёт остатков: Код, Наименование, Изображение, Доступно, Цена продажи. Excel загружается в браузере владельца; перед сохранением можно заполнить цены, а фото сжимаются.

Пока `BOT_TOKEN` не задан, приложение показывает только демонстрационный предпросмотр. При отсутствующем `ORDER_CHAT_ID` оформление заказов заблокировано, чтобы заказ не потерялся без канала. Изменение количества в опубликованном поступлении не может сделать остаток ниже уже оформленных заказов. При повторном импорте файл содержит **исходное количество**, а не текущий остаток.


## Колонки отчёта остатков

| В Excel | В приложении |
|---|---|
| Код | Артикул |
| Наименование | Наименование |
| Изображение | Изображение |
| Доступно | Кол-во |
| Цена продажи | Цена |

«Код» имеет приоритет над «Артикул», «Доступно» — над «Остаток» и «Кол-во», «Цена продажи» — над другими ценами. «Резерв» и «Сумма продажи» не используются для расчёта количества и цены. Пустая цена продажи требует заполнения перед сохранением, даже если другая цена указана. Порядок колонок и регистр названий не важны. Встроенные фото XLS/XLSX сопоставляются с товарами по строкам и сжимаются при импорте.

## Ручные группы товаров

После загрузки Excel можно сразу сохранить поступление. Без ручного распределения товары отображаются в порядке строк файла, без групп, поиска и фильтра по группам. Автоматического анализа названий и подгрупп нет.

Для группировки в редакторе поступления введите название и нажмите «Создать группу», затем выберите группу у нужных товаров. Необязательно распределять все позиции: оставшиеся товары отображаются в разделе «Без группы». Можно переименовать или удалить группу, либо нажать «Убрать все группы», чтобы вернуться к обычному списку. Пустые группы сохраняются для дальнейшего распределения, но не отображаются покупателям.

При обновлении того же поступления назначения совпадающих артикулов сохраняются, новые позиции остаются без группы, порядок обновляется по новому файлу. Старые автоматические группы не используются: ручное распределение задаётся заново через «Изменить». Заказы и остатки сохраняются.
